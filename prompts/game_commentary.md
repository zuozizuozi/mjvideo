# 试玩解说：从一段无声录屏做成一期社媒视频

给 Agent 看。用户只给**无声录屏**（长短、内容都不保证），可能不给稿子。你负责：看懂录屏 → 挑高光 → 写解说 → 剪辑和标注 → 配音字幕配乐 → 封面、标题、文案。
主题永远是**"AI 做的游戏，能做到什么程度"**：既是试玩，也讲制作过程。

## 流程

```
mjv_new_project（template=gameplay，game=游戏 slug）
→ mjv_games（读事实）+ 读游戏仓库的 README / DESIGN / PROGRESS
→ mjv_footage（导入录屏，看报告和拼图）
→ 写分镜（project.json 的 shots）
→ mjv_run tts → timeline → check → mjv_stills（核对画面和解说对得上）
→ 给用户看脚本 + 静帧（用户说过"直接出"就跳过）
→ mjv_run render → audio → mux → validate
→ mjv_cover → 标题和文案 → 交付
```
用户在工作台里可能已经选了游戏、传了录屏、写了意见：先 `mjv_notes`、`mjv_project_info`。

## 一期的结构（60–90 秒，竖屏；顺序可以调，不要每期一模一样）

| 段落 | 时长 | 内容 | 常用画面 |
|---|---|---|---|
| 钩子 | 3–5 秒 | 最炸的那个画面 + 一句反差 / 悬念 | `footage_play` fill 版式 + 推近；或定格 + 一个标注 |
| 一句话玩法 | 5–8 秒 | 这是什么游戏、怎么玩、目标是什么 | `footage_play` fit 版式 + 上方游戏名 + "实机录屏"角标 |
| 试玩高光 ×2–4 | 每段 6–10 秒 | 每段讲一个亮点，**落到"AI 做了什么"** | `footage_play` + 标注（框 / 圈 / 放大镜）、慢放、定格 |
| 制作过程 ×1–3 | 每段 5–8 秒 | 给 AI 的指令、设计文档里的一句话、几天做完、代码量 | `doc_quote`、`milestone_timeline`、`stat_cards`（也可以自己写新场景） |
| 收尾 | 4–6 秒 | 一句话结论 + 一个能让人评论的问题 | `footage_play` card 版式 + 定格 |

## 怎么"看"录屏

1. `mjv_footage` 返回报告 + 全片概览拼图 + 高光候选细看拼图。每格左上角是录屏时间，白线是 10% 网格。
2. 先看**全片概览**：录屏里有哪几段内容（菜单、教程、战斗、Boss、结算……），各在什么时间。报告里 `·` 是静止 / 黑屏，基本都要剪掉。
3. 再看**高光候选**：运动量最高的几段，通常是动作最激烈的地方，但不一定最好看。结合游戏的"拍视频建议"（`mjv_games` 的 filming 字段）判断。
4. 需要更细的画面时，用 `mjv_stills` 渲染你写好的镜头来核对，或者用文件工具读 `footage/` 里的其他拼图。
5. **你看到的是每 0.5–1 秒一帧**：快速动作的细节可能看不清。解说讲"这一段发生了什么"，不要编造看不清的细节（比如具体打出了多少伤害）。

## 写解说

- **一个镜头一句话**，15–40 个字，口语、完整句子。数字和英文容易读错时用 `tts` 字段写读音版。
- **讲画面上正在发生的事**：观众看到巨龙盘身，你就讲巨龙；不要画面在骑车、解说在讲代码量。
- **每段落到 AI 能力**，但要具体：不说"AI 很厉害"，说"这条龙是代码一个顶点一个顶点算出来的，没用一张贴图"。
- **只用真实的事实**：数字只能来自 `mjv_games` 的 facts 和游戏仓库的文档（README / DESIGN / PROGRESS / 提交记录）。查不到的不要说。示意的内容画面上标"示意"。
- **如实讲不足**：画面里有 bug、穿模、卡顿，可以大方讲一句"这里还有点小问题"，可信度更高。
- 账号规范：字幕和画面里**不出现模型名、工具名、网址**（口播可以说"AI"；需要时 `tts` 字段和 `text` 分开写）。游戏链接只放在发布文案里。

## 解说和画面对齐

- 配音模式的镜头时长 = 这句话的配音时长 + `hold`。`params.in` 是这个镜头从录屏第几秒开始放。
- **算一下够不够长**：镜头时长 × `speed`（加上慢放）不能超过录屏剩余长度，也不要跑进静止段。录屏不够长时：用 `slow` 慢放、`freezeAt` 定格，或者换一段。
- 标注、慢放、定格的 `at` 写解说词里的词，说到这个词时发生。一个镜头最多 1–2 个标注，标注要标在画面真正有东西的地方（按网格读坐标，`mjv_stills` 核对）。
- 镜头之间：动作镜头之间用 `cut`（快），换段落用 `slide` 或 `fade`。

## 版式

| 录屏 | 用法 |
|---|---|
| 横屏录屏，讲解为主 | `fit`：录屏居中，上方放游戏名和副标题，背景是模糊的录屏，字幕在下方 |
| 横屏录屏，动作为主 | `fill`：裁满竖屏，`focus` 对准主角（按网格），配 `zoom` 缓慢推拉 |
| 竖屏录屏（例如萤渊） | `fill`，基本不用裁 |
| 收尾 / 强调 | `card`：录屏做成卡片，背景跟随主题 |

风格（`theme`）可以选一个风格包或自定义，制作过程的画面会跟着变；录屏画面不受影响。电影感（`cinema`）的遮幅会挡住竖屏上下，试玩解说慎用。

## 交付

1. 成片：`output/成片.mp4`，复制到 `C:\Users\Administrator\Desktop\opus视频\<编号>_<游戏名>试玩\`（用户的约定，没有这个目录就问一下）。
2. 封面：`mjv_cover`，标题用 | 换行，每行 ≤ 8 个字。3:4 和 9:16 两张。
3. 标题：16–20 个字，有传播度（反差、悬念、数字），不出现模型名。
4. 发布文案：开头一句钩子 + 两三句内容 + 一个互动问题 + 话题标签；游戏链接可以放在这里。
5. 向用户报告：用了录屏的哪几段、讲了哪些事实（出处）、哪里不确定、配音用的是 AI 声音还是本人音色。
