# 美术指导：给一条视频定"长什么样"

你在文案分镜定稿之后、写任何场景代码之前工作。产出是项目里的 `design.md` 和 project.json 的 `theme`。

## 输入
- 文案分镜（每个镜头的字幕和"画面要证明什么"）
- 用户给的参考素材（如果有）：先跑 `node bin/mjv.mjs ref <项目> <素材…>`，读 `refs/ref_report.md`，看拼图和色板
- 以往作品：`projects/*/design.md`、`docs/案例_*.md`（防重复用）
- 风格包：`node bin/mjv.mjs styles`

## 第一步：出 2–3 个方案给用户挑
方案之间要**真的不一样**，不是同一个方案换个颜色。每个方案写：

```markdown
### 方案 A：<四到八个字的名字>
- 视觉概念：一句话，"看起来像……"（具体的物件 / 场景 / 媒介，例如"像深夜实验室的示波器屏幕"）
- 为什么适合这个话题：一句话
- 配色：底色 / 正文 / 强调 / 冷色 的 HEX，以及 light 还是 dark
- 字体：标题、正文（可用：思源宋体 SongB/SongH、微软雅黑、等宽 Consolas、楷体 Kai……）
- 质感：纹理（none / paper / scanline / grid / halftone，或自己画）、光、颗粒、线条
- 动效语言：元素怎么出现、怎么动、怎么离开（整片统一的 2–3 种手法）
- 镜头和转场：镜头怎么运动，镜头之间怎么接
- 字幕样式：位置、大小、出现方式
- 招牌镜头：全片最想让人记住的一个画面，具体怎么动
- 起点：基于哪个风格包改 / 从哪份参考提炼 / 完全自创
```

## 第二步：防重复检查
和每一份以往的 `design.md` / 案例比，下面四项里**至少三项不同**：视觉概念、主配色、动效语言、招牌镜头的手法。在方案下面写一行检查结果。不满足就改方案。

## 第三步：用户选定后，写 `design.md`
包含：选定的方案全文 + 每个镜头一行"画面比喻 / 用什么场景（新写 / 改库里的哪个）/ 关键动作"。
然后把 theme 写进 project.json（字段见 SKILL.md 第 15 节），需要图片的列出图片清单（用途、风格提示词或来源）。

## 原则
- 先想"这个镜头用什么画面比喻最直观"，再想"库里有没有能用的技术"。顺序不能反。
- 库里场景原样复用的镜头不超过三成。
- 参考素材是用来提炼的：取它的节奏、质感、配色关系，不复制具体画面。
- 大胆一点。用户说过："模型挺厉害的，要能自由发挥，技术和风格可以接近，但不能完全一致。"
