# 场景作者提示词（为一个知识点写新的动画场景）

你要为一个镜头写一个新场景文件 `projects/<项目名>/scenes/<场景名>.js`。输入：这一镜的口播 `text`、动作词、`note`（画面要证明什么）。

## 先想清楚再写
1. **这个知识点“长什么样”？** 找到它最本质的视觉对象和关系：
   - 熵力 → 一条受热抖动的分子链，两端距离和“可能的形状数”此消彼长；
   - 发动机 → 曲柄转一圈，活塞上下一次，四个冲程依次发生；
   - 行星轨道 → 椭圆、近日点快远日点慢（开普勒第二定律，扫过面积相等）。
2. **用什么关系驱动动画？** 优先用真实的数学或物理关系算位置，而不是手摆关键帧。
   简化可以，但定性要对；示意性的数值要在画面上标“示意”。
3. **每个动作词对应画面上的哪一个变化？** 列出来：动作词 → 变化 → 持续多久。
4. **选视觉语言**：配色、字体、质感要服务于知识点（纸笔、蓝图、霓虹、水墨……），可以参考 `engine/scenes/` 里 11 个场景的做法。

## 写代码
- 从 `templates/scene.template.js` 开始，或者参考 `projects/demo_rubber_entropy/scenes/polymer_chain.js`（完整的新知识点示例）。
- 遵守 SKILL.md 第 2 节的硬性规则：确定性（只依赖 u）、每帧铺背景、恢复画布状态、半径和除数防越界、静态内容在 create 里预画、关键信息放在安全区 y 180–1420。
- 动作词全部放进 `params.cues`；常改的文字、数量也做成参数。
- `title` 和 `desc` 一定写好，desc 写“画什么 + 适合讲什么知识点”。

## 验证
```bash
node bin/mjv.mjs check projects/<项目名>
node bin/mjv.mjs stills projects/<项目名> <每个动作词之后 0.5 秒的时间点…>
```
看静帧，对照 SKILL.md 第 4 节的清单逐条检查，改到满意再交给渲染。
