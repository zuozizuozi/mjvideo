## 1. 回归测试：重新渲染《一行代码，怎么变成一段视频？》

项目：`projects/regress_code_video`；基准：`reference/成片_原版.mp4`（原工程交付的成片）。
配音复用原版音频文件（edge-tts 每次合成会有细微差别，复用才能逐帧比较）。

| 检查 | 结果 |
|---|---|
| 时间轴（总时长、46 条字幕、11 个镜头的逐字时间） | 与原版 `timeline.json` **完全相同** |
| 加载检查 `check` | 11 个镜头无报错，46 条字幕宽度正常 |
| 画面（按帧号严格对齐，原版 2913 帧全部比较） | 最低 43.57 dB，1% 分位 45.54 dB，中位 53.12 dB，**没有一帧低于 35 dB**，差异只来自编码 |
| 帧数 | 新版 2915 帧（= 时间轴应有帧数）；原版 2913 帧，原版被 `-shortest` 截掉了最后 2 帧，新流程修复了这个问题 |
| 人声轨 voice.wav | 与原版**逐采样一致** |
| 配乐轨 bgm.wav | 与原版**逐采样一致** |
| 音效时间点（41 个） | 与原版**完全一致** |
| 音效波形 | 噪声成分不同：原版用 Python `hash()` 做种子，每次运行都会变，本身不可复现；新版改成固定种子 |
| 响度 | 原版 −14.4 LUFS，新版 −14.4 LUFS |
| 质检 `validate` | 通过（2915 帧，音画 97.17s / 97.17s） |
| 渲染耗时 | 285 秒（原版 279 秒） |

**注意比较方法**：一开始用 FFmpeg `psnr` 默认的按时间戳配对，得到一批 3–25 dB 的“差异帧”，逐帧取出比较后确认是配对错位（同一帧号的画面 PSNR 42–47 dB）。改成 `setpts=N/30/TB` 按帧号对齐后结果如上。README 里写的是正确的比较命令。

## 2. 确定性

| 检查 | 结果 |
|---|---|
| 同一项目连续两次完整渲染（2915 帧），解码后整片 MD5 | **完全相同** |
| 单独重渲 s06–s08 后与完整渲染逐帧比较 | s07、s08 逐像素相同；s06（合成波，大量 `shadowBlur` 发光）有 250 帧存在微小差异，PSNR 47.5–56.8 dB，差异只在发光边缘，肉眼不可见 |

结论：同样的渲染顺序完全可复现；带强发光效果的镜头单独重渲时可能有 1–2 级像素误差（Chrome 绘制模糊阴影不保证逐像素一致）。

## 5. 复用测试：换讲稿，只改参数
