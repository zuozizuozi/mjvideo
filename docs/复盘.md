# 复盘：《一行代码，怎么变成一段视频？》是怎么做出来的

依据：备份在 `../backup/08_风格展示_代码画视频_原版/` 的真实文件（script.json、tts.py、build_timeline.py、web/show.js、render.mjs、audio.py、cover.py、out/render.log）和制作时的执行记录。
同一会话里先做的《AI说改好了你就信？》（`../backup/07_样片_AI说改好了_原版/`）是这套方法的第一版，相关经验一并记录。

## 1. 讲稿和叙事结构

- 题目由我定：「一行代码，怎么变成一段视频？」。选这个题的原因：视频本身就是答案，每讲一个原理就换一种画风演示，风格多样是讲解的需要，不是硬堆。
- 结构是**递进链**，每一段都回答上一段留下的问题：
  拍的吗？不是，是代码画的 → 视频的本质（手翻书，一秒 30 张）→ 每张图是什么（像素）→ 怎么动起来（位置是时间的函数）→ 为什么不僵（缓动）→ 怎么有立体感（透视除法）→ 怎么有纵深（分层视差）→ 复杂画面怎么来（简单规则 + 很多粒子）→ 怎么变成文件（逐帧渲染 + 编码）→ 好处（改个数字就重出）→ 收尾。
- 写法：一镜一段，每段 25–45 字，读出来 6.5–9.5 秒；句子是完整口语，不拼词；每段里埋 2–4 个**能触发画面动作的词**（例如“三十张图”“除法”“松手”），后面动画就按这些词对点。
- 讲稿存在 `script.json` 的 paragraphs 里，每段带 `scene`（场景名）和 `name`（风格标签）。

## 2. 每个镜头的视觉风格和动画形式

决定方法：**先问这个知识点“长什么样”，再选一个能把它演出来的视觉语言。**

| 知识点 | 选的风格 | 理由 |
|---|---|---|
| 不是拍的，是代码 | 终端 + 代码雨 | 代码最直观的样子；帧号用真实帧数实时跳动 |
| 视频 = 手翻书 | 笔记本纸 + 铅笔小人 | 手翻书本来就是纸和铅笔 |
| 像素 | 8-bit | 像素风本身就是“看得见像素” |
| 位置是时间的函数 | 工程蓝图 | 函数图 + 读数，像工程图纸 |
| 缓动 | 纸艺 | 柔软的纸质感配“有重量”的动作，落地挤压 |
| 透视 | 合成波 | 透视网格地面是合成波的标志 |
| 分层视差 | 水墨 | 远山近山本来就是水墨的层次 |
| 简单规则涌现 | 粒子 | 1500 个点聚成字 |
| 逐帧渲染流程 | 瑞士海报 | 大数字计数 + 流程条，信息感强 |
| 改个数字 | 漫画波普 | 夸张的“改个数！”爆炸框 |
| 收尾回顾 | 胶片 | 胶片里滚动播放前面镜头的真实画面 |

每个场景的动画都和口播对点：说到“三十张图”才出现分帧条，说到“除法”公式才弹出，说到“聚成字”粒子才开始聚拢。

## 3. 动画是怎么写的

- **这条片子全部用 Canvas 2D**（`web/show.js`，一个 1080×1920 的画布），没有用 SVG、DOM 动画或 Three.js。
  上一条《AI说改好了》用的是 DOM + CSS + SVG（`web/app.js`），所以两种都实际跑通过。
- 核心规则：**画面只由时间 t 决定**。渲染器调用 `window.seek(t)`，每个场景函数 `draw(c, u)` 只依赖镜头内秒数 u，没有 `Math.random()`、`requestAnimationFrame` 或 CSS 过渡。随机布局用固定种子的 `rng(seed)`（mulberry32）。
- 常用工具：`pr(u, 起点, 时长, 缓动)` 给出 0→1 的进度；缓动有 out / inOut / back / elastic；`typed()` 做打字机；`rr()` 画圆角矩形。
- 具体技巧（都在源码里）：
  - 像素化：先把矢量图画到小画布，再关闭平滑放大（`imageSmoothingEnabled=false`）
  - 透视：屏幕坐标 = f × 高度 ÷ 距离，地面横线按距离循环流动
  - 水墨：每层山脊是带种子的随机折线，竖向渐变填充，不同层按 1:3:9 的速度平移
  - 粒子：游走用多个正弦叠加，聚字时插值到从文字像素里采样出的目标点，`globalCompositeOperation="lighter"` 发光
  - 胶片：开场时把前 10 个场景各画一帧（72% 处）缩成缩略图，滚动播放

## 4. 时间轴、帧率、转场

- 30fps，总帧数 = round(总时长 × 30) = 2915。
- 时间轴来自配音：开头留 0.5 秒，镜头之间空 0.55 秒，结尾留 3.2 秒。
- 每个镜头的场景在自己的口播时间内运行；镜头边界取“上一段说完”和“下一段开始”的中点，前后各 0.32 秒做转场（两个场景各画到缓冲画布，再按转场方式合成）。
- 转场 5 种：glitch（错位切片）、pixel（像素化）、wipe（斜切擦除）、circle（圆形展开）、slide（上推），按镜头指定。

## 5. 配音、字幕、音画同步

- 配音：edge-tts，晓伊（`zh-CN-XiaoyiNeural`，+4% 语速），**每段整段合成**，同时拿到 WordBoundary（逐词时间）。
- `build_timeline.py` 把逐词时间对回原文，得到**逐字的绝对时间**（`chars` 数组）。动画里的 `cue("词")` 就是查这个词第一个字的时间。
- 字幕：先按句号切句，再按标点切；太长的用 jieba 分词，在最接近中点的词边界切开；时间取每条字幕第一个字的时间。
- 音画同步靠同一份时间轴：画面的 cue、字幕、音效、配音的放置位置都从它算出来。

## 6. 渲染和合成

- `render.mjs`：启动无头 Chrome（`--headless=new` + 远程调试端口），用 Node 24 自带的 WebSocket 直接说 DevTools 协议，不装任何 npm 包。
  每帧：`Runtime.evaluate("seek(t)")` → `Page.captureScreenshot`（JPEG 92）→ 写进 FFmpeg 的标准输入（image2pipe）→ libx264 crf17 yuv420p。
- 2915 帧用了 279 秒（约 10 帧/秒）。
- 声音：`audio.py` 纯 Python 合成配乐（100 BPM，Am-F-C-G，每个风格一种音色）和音效（时间点来自场景代码登记的 `sfx()`），人声做高通、提亮、-16 LUFS，配乐用侧链压缩随人声压低，总响度 -14 LUFS。
- 最后 FFmpeg 把画面和混音合成 MP4。

## 7. 出过的问题和修法

| 问题 | 现象 | 原因 | 修法 |
|---|---|---|---|
| 渲染卡死近 2 小时 | 后台渲染没有动静，没人发现 | 渲染进行中又跑了抽帧，两个进程用了同一个调试端口，抽帧把渲染的页面抢走；输出被 `tail` 吞掉，看不到进度 | 每次随机端口；DevTools 调用 30 秒超时报错；进度写日志文件并检查 |
| 场景初始化崩溃 | `arc` 半径为负 | 合成波灯柱的距离取模后可能为负 | 取模结果归正，太近的灯柱不画 |
| 灯柱太大 | 最近的灯柱竖着穿过字幕 | 距离很小时缩放过大 | 只画距离 ≥ 1.3 的灯柱并淡入 |
| 标题贴边 | 终端大标题碰到右边 | 字号偏大 | 96 → 84 |
| 粒子太暗 | 聚字前几乎看不见 | 半径和透明度太小 | 半径 4.2，透明度 0.8 |
| 封面取错帧 | 两格都是终端 | 取的 8.5 秒还在第一镜 | 按时间轴取各镜头中段的时间 |
| 成片少 3 帧 | （这次工程化时才发现）原版 97.12 秒，时间轴 97.16 秒 | 合成时用了 `-shortest`，音频略短就把最后几帧画面截掉 | 音频补静音，按画面精确时长输出；验证器检查帧数 |

《AI说改好了》那条遇到过的问题：字幕在词中间断开（改成按 jieba 词边界单行切分）、几个元素互相遮挡（逐帧抽查后调整坐标）、旧版 Pillow 不支持圆角矩形和负坐标贴图（自己实现）。
